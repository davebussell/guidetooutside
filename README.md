# Guide to Outside — guidetooutside.com

Enter a town, city, ZIP or postal code (Canada + US) and get a seasonal field guide for **gardening, fishing and foraging** in that area: estimated hardiness zone and frost dates, this week's forecast and soil temperature, moon phase and solunar rating, named waters within 20 km, a link to the official fishing regulator, and an AI-written plan for the week.

Built with Next.js 16 (App Router) + Tailwind 4. No database required.

## How it works

| Step | Source | Cost |
|---|---|---|
| Geocode the query (city / postal / ZIP) | OpenStreetMap Nominatim, Open-Meteo geocoding fallback | free |
| Forecast, current conditions, soil temp, sunrise/sunset | Open-Meteo forecast API | free |
| Hardiness zone + average frost dates (10-yr reanalysis) | Open-Meteo archive API (ERA5) | free |
| Moon phase / solunar | computed locally | — |
| Named lakes & rivers within 20 km | Overpass (OpenStreetMap) — best effort | free |
| Fishing regulator link | built-in table for all provinces/territories/states (`src/lib/regs.ts`) | — |
| The written guide | Anthropic Claude via tool-use (structured JSON), **cached one week per ~10 km cell** | ~1–3¢ per new area per week |

Without `ANTHROPIC_API_KEY` the site still works: a rules-based seasonal guide (`src/lib/guide-rules.ts`) renders instead. Every shipped page is server-rendered and indexable (`/guide/kingston-ontario`), so it doubles as an SEO surface.

## Live deployment (Netlify)

The site is deployed on Netlify as project **guidetooutside** (https://app.netlify.com/projects/guidetooutside) with the custom domain guidetooutside.com (GoDaddy DNS: `@` A → 75.2.60.5, `www` CNAME → guidetooutside.netlify.app; www redirects to the apex).

- Deploy from this folder: `NETLIFY_AUTH_TOKEN=… npx netlify deploy --build --prod` (or connect the GitHub repo in Netlify for deploys on push).
- **AI guides run through Netlify's built-in AI Gateway** — Netlify injects `ANTHROPIC_API_KEY`/`ANTHROPIC_BASE_URL` automatically, billed to the Netlify account. To use your own Anthropic key instead, set `ANTHROPIC_API_KEY` in Netlify env vars (it overrides the gateway) or disable the AI Gateway in project settings.
- Guides are cached in **Netlify Blobs** (store `guides`) for a week per ~10 km cell; no Redis needed on Netlify.
- `ANTHROPIC_MODEL` is set to `claude-haiku-4-5` for speed; each section is a separate ~10 s call. Sonnet gives richer guides but roughly doubles generation time.

## Deploy to Vercel (alternative)

1. Push this folder to a GitHub repo.
2. In Vercel: **Add New → Project → import the repo**. Framework auto-detects as Next.js. Deploy.
3. **Settings → Environment Variables** — add at minimum:
   - `ANTHROPIC_API_KEY` — from console.anthropic.com
   - `NEXT_PUBLIC_SITE_URL=https://guidetooutside.com`
   - Optional but recommended: `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` (Vercel Marketplace → Upstash Redis, free tier) so one AI generation is shared by everyone in the same area for a week. Without it, caching is per-server-instance only.
4. Redeploy after adding variables.

### Point guidetooutside.com (GoDaddy) at Vercel

1. Vercel → Project → **Settings → Domains** → add `guidetooutside.com` and `www.guidetooutside.com`. Vercel shows the records it wants.
2. GoDaddy → **My Products → DNS** for guidetooutside.com:
   - **A** record: name `@` → value `76.76.21.21` (Vercel's apex IP; confirm the value Vercel displays)
   - **CNAME** record: name `www` → value `cname.vercel-dns.com`
   - Delete GoDaddy's default "Parked" A record and any conflicting `www` record.
3. Back in Vercel the domain flips to *Valid* within minutes (up to an hour). SSL is automatic.
4. Set `www` → redirect to apex (or the reverse) in Vercel's domain settings so there's one canonical host.

## Monetization & lead capture

| Env var | What it enables |
|---|---|
| `NEXT_PUBLIC_ADSENSE_CLIENT` | Loads AdSense and renders two responsive units on every guide page (`AdSlot` in `src/components/Monetize.tsx`). Replace the `data-ad-slot` names with your real slot IDs once created. |
| `NEXT_PUBLIC_AMAZON_TAG` | Adds your Associates tag to the "Useful gear" links under each section (amazon.ca for Canadian locations, amazon.com for US). |
| `NEXT_PUBLIC_GA_ID` | Google Analytics 4. |
| `NEWSLETTER_WEBHOOK_URL` | Newsletter form POSTs `{email, source, location}` to any webhook — Zapier/Make/n8n → Beehiiv, Mailchimp, ConvertKit, a Google Sheet, etc. |
| `BUTTONDOWN_API_KEY` | Or subscribe directly to Buttondown, tagging each subscriber with their location. |

The newsletter itself (the "Weekly Field Note") is not generated by this repo yet — subscribers are captured with their location so a weekly job can call the same `generateGuide()` per area and send it. That's the natural next step.

## Notes & known limits

- Hardiness zone and frost dates are **estimates** from ERA5 reanalysis (grid ≈ 10–25 km), typically within half a zone / a week or two of official station values. Near large lakes or in mountain valleys they can drift more; the UI labels them as estimates.
- Overpass (nearby waters) is rate-limited and occasionally slow; the page degrades gracefully and the AI still names regional waters from its own knowledge.
- Nominatim's usage policy asks for a real contact in the User-Agent (set in `src/lib/geocode.ts`) and ≤1 req/s; results are cached 30 days. If traffic grows, swap in a paid geocoder (Mapbox, Google) in that one file.
- Fishing seasons and limits are never stated as fact — the guide points at the regulator table in `src/lib/regs.ts`. Review those URLs once a year.
